# pwnable.tw Decision Casebook

This is the explicit entry point for all 43 migrated pwnable.tw challenge records. Start at the Decision Router, select the row matching the observed trigger, concrete defect, primitive, libc/protection evidence, or aliases, and follow that row to one case. The router is intentionally more specific than the source tag index: tags such as `rop` or `use-after-free` describe a family, while a Decision Router row identifies the exact trigger and challenge-specific path.

## Scope and Provenance

- Source: `/home/hungnt/pwn-knowledge-base/linux-userland-ctf/pwnable.tw` (43 challenge `README.md` files, `index.md`, and `patterns_archive.md`).
- Source organization: one normalized challenge record per directory plus a canonical platform index; `patterns_archive.md` contains the 28 generic code-audit patterns and is represented by [source-red-flags.md](source-red-flags.md).
- Authorized use: replay, study, and defensive analysis of public CTF challenges only. This is not operational guidance against non-consenting systems.
- Historical-data note: service strings, ports, flags, artifact names, write-up IDs, solution counts, probabilities, platform versions, and locally observed libc offsets are retained as historical CTF evidence. They are not guarantees about the current live service and must not be treated as reusable constants on other targets.
- Information partition: reusable source patterns live in [source-red-flags.md](source-red-flags.md); exact challenge facts, paths, flags, assets, and provenance live only in these case files. Technique files may link to cases but do not restate their exact payloads.

## Case Files and Technique Routes

- [stack-control-cases.md](stack-control-cases.md) - **Start when attacker data reaches a return address, saved EBP, code pointer, or format function.** Techniques include return-address overwrite, canary bypass/leak, stack pivot, ret2plt/ret2libc, syscall ROP, ret2csu, SROP, ret2dlresolve, format-string leak/write, and closed-FD recovery. Example chains: 24-byte arbitrary write → `.fini_array` → pivot → static `execve`; attacker-length `strncmp` → password oracle → `strcpy` overflow → ROP; calculator index underflow → stack AAR/AAW → ROP; blind `printf` → `.fini_array` re-entry; writable GOT low byte → adjacent syscall → SROP.
- [heap-object-cases.md](heap-object-cases.md) - **Start when a program/C++ object, array entry, vtable, or type tag is stale, confused, or wrongly reused.** Techniques include UAF, double free, dangling function pointer, fake object, vtable overwrite, type confusion, C++ copy-constructor/assignment/destructor lifetime bugs, stack-node-in-heap-list confusion, GOT overwrite, and object-driven heap R/W. Example chains: global note UAF → fake print pointer → GOT leak → `system`; missing C++ copy constructor → temporary destructor double-free → fastbin dup; cart node on stack → unsafe unlink → EBP pivot.
- [allocator-file-cases.md](allocator-file-cases.md) - **Start when malloc/free/realloc chunk state, bin links, chunk sizes, or FILE structures create the primitive.** Techniques include tcache poisoning, fastbin/unsorted-bin attacks, House of Orange/Spirit/Einherjar-style consolidation, top-size corruption, unsafe unlink, off-by-null/backward consolidation, chunk overlap, fake BSS chunks, `__malloc_hook`/`__free_hook`, one-gadget/setcontext, and `_IO_FILE`/`fclose`/stdout/stdin vtable hijack. Example chains: freed pointer retained → tcache poison → BSS fake chunk → hook; `strlen` resize → top-size corruption → House of Orange; fake FILE → `fclose` vtable → `system`.
- [shellcode-sandbox-cases.md](shellcode-sandbox-cases.md) - **Start when bytes must execute or a syscall policy decides the finish.** Techniques include alphanumeric/printable/self-modifying shellcode, shellcode stagers and jump chains, RWX BSS/heap execution, mprotect, `execve`/ORW syscalls, negative-index GOT execution, seccomp BPF analysis, emulator/kernel policy differentials, and x86-64 `retf` architecture switching. Example chains: alphanumeric notes → GOT execution; chemical-formula buffer → `call eax`; ORW-only seccomp → open/read/write; x64 `retf` bypass.
- [restricted-shell-cases.md](restricted-shell-cases.md) - **Start when the issue is shell policy, executable loader, chroot, bash internals, or descriptor reachability rather than ordinary libc corruption.** Techniques include `chmod o-x` loader bypass, restricted-command execution, bash `popd` controlled free (CVE-2016-9401), bash allocator/SHELL_VAR/function reclaim, `/proc/self/mem` builtin overwrite, chroot escape, raw socket creation, and leaked/reused file descriptors. Example chains: retained `ld-linux` → allowed interpreter; `popd +-N` → controlled free → shell-variable hijack → raw-socket flag FD.

## How To Use This Casebook

Use this Decision Router before generic technique references whenever a target is known or reasonably suspected to be pwnable.tw. Select a row by concrete evidence: challenge name, service behavior, parser/menu, memory-corruption trigger, C++/allocator structure, libc version, protections, seccomp policy, or aliases. Points are historical metadata, not exploit selectors.

Follow the `Exact anchor` link directly. Read the challenge route card, then `Metadata`, `Facts`, `Exploit Paths`, and `Assets and Provenance` in that case. The case record is authoritative for exact offsets, libc constraints, historical flags/ports, failure probabilities, negative findings, and artifacts. Generic technique files explain reusable background; they never replace case-specific constraints.

## If You Do Not Know The Technique Yet

Work in this order:

1. **Find where attacker input is stored or interpreted.** A long input that crashes after a function returns points to stack control; a direct `printf(input)` points to format string; a menu allocation that remains usable after delete points to UAF.
2. **Classify the first wrong operation.** Wrong size/copy means overflow; freed-but-used/double-released means lifetime; wrong bin/size/link means allocator corruption; wrong C++/language object shape means type confusion; blocked syscalls mean seccomp/ORW; shell restrictions mean restricted shell.
3. **Use the matching symptom row below**, then confirm the exact case in the Decision Router. Do not choose a case from the final payload: a heap UAF that ends in ROP belongs with the heap UAF.

| `printf`/`syslog`/`sprintf` receives attacker-controlled format data | format-string leak/write, `%n`, GOT overwrite, blind format string | [stack-control-cases.md](stack-control-cases.md) |

## Misrouting Rules

- If an object/array lifetime, C++ copy/destructor, function/vtable pointer, or language-object confusion creates the first primitive, start in `heap-object-cases.md`.
- If malloc/free/realloc/tcache/fastbin/unsorted/House/chunk-overlap or `_IO_FILE` mechanics create the first primitive, start in `allocator-file-cases.md`.
- If seccomp appears after a heap primitive, start in the allocator case and use `shellcode-sandbox-cases.md` for the sandbox finish.
- Route by the first exploitable defect, not by the final payload type: a UAF that ends in ROP is still a UAF case.
- Restricted-shell cases are for bash/loader/chroot/FD constraints, not ordinary libc `system("/bin/sh")` chains.
